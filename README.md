# 안진 · 건축물 안전지원 플랫폼

지역별 공고문과 건축물대장을 대조하여 지원 대상 건축물을 검토하고, 소유자에게 안내하는 한국어 웹 애플리케이션입니다.

**구현 범위:** PDF·이미지의 OpenAI Vision OCR 및 LLM 조건 추출, 담당자 조건 승인, 결정적 조건 대조, CSV 일괄 등록·결과 다운로드, 소유자 연락 동의 기록, Solapi LMS 발송, SQLite 발송 이력과 중복 방지입니다. 처음 표시되는 공고·건축물·이름은 모두 가상 예제입니다.

## 실행

Node.js **24 이상**이 필요합니다. 외부 npm 패키지를 사용하지 않아 `npm install` 없이 실행됩니다.

```sh
git clone https://github.com/yoomh7583-dev/mongil.git
cd mongil
cp .env.example .env
npm start
```

브라우저에서 `http://127.0.0.1:3000`에 접속하세요. 키 없이 공고·건축물 직접 입력, 예제 체험, 조건 대조, CSV, 문자 시뮬레이션을 사용할 수 있습니다.

## 실제 OCR·LLM과 문자 연결

`.env`에 다음 환경변수를 입력하고 서버를 다시 시작합니다. 실제 키와 DB는 Git에 올리지 않습니다.

| 환경변수 | 용도 |
| --- | --- |
| `APP_ADMIN_TOKEN` | 최소 24자 임의 문자열. 웹 설정 화면의 서버 연결 토큰 |
| `OPENAI_API_KEY` | 문서 OCR·지원 조건 추출용 OpenAI API 키 |
| `OPENAI_MODEL` | 기본 `gpt-4.1-mini`, 이미지·PDF 입력과 JSON 출력 지원 모델 |
| `SMS_ENABLED` | 실제 발송 시에만 `true`, 기본 `false` |
| `SOLAPI_API_KEY` / `SOLAPI_API_SECRET` | Solapi 인증 정보 |
| `SOLAPI_SENDER` | Solapi에 등록·인증된 발신번호 |
| `HOST` / `PORT` | 기본 `127.0.0.1:3000` |
| `DATA_DIR` | 기본 `./data`, SQLite 영속 저장 경로 |

토큰 생성 예: `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`

토큰 설정 후 웹의 **설정 → 서버 연결**에서 입력합니다. 키는 서버에만 저장하며 브라우저에는 전송하지 않습니다. 토큰을 교체하면 기존 연결은 무효화됩니다. 운영 환경은 HTTPS 뒤에서 단일 담당자용 서버로 배포하세요. 인터넷 공개 전에 조직의 계정·권한 체계, 백업, 개인정보 보관·삭제 정책을 추가해야 합니다. 외부 주소로 바인딩할 때는 관리자 토큰이 필수입니다.

## 사용 순서

1. **공고문 관리:** PDF·PNG·JPEG·WEBP(최대 10MB) 또는 텍스트를 등록합니다. LLM은 지원·제외 조건과 원문 인용을 추출합니다. HWP는 PDF로 변환하세요.
2. **조건 검토:** 기준일, 마감일, 지원 조건, 제외·예외 조건과 OCR 원문을 확인합니다. 미해석 조건을 해결하고 검토 확인란을 선택해 승인합니다. 초안 저장도 가능합니다.
3. **건축물 관리:** 대장 업로드·직접 입력 또는 UTF-8 CSV로 건축물을 등록하고 원문과 대조합니다. 연락처와 동의 기록은 별도로 확보·입력합니다.
4. **대상 판정:** 각 건축물의 실제값과 지원 조건, 원문 근거를 확인합니다. 경과 연수는 공고 기준일의 월·일까지 계산합니다.
5. **문자 발송:** 대상 건축물을 선택하고 안내 문구·문의 연락처를 수정합니다. 시뮬레이션 또는 최종 확인 후 실제 발송합니다. 1회 최대 20명입니다.

## 판정 원칙과 한계

- 승인된 조건은 **AND**로 대조합니다. `eq`, `in`, `gte`, `lte`, 날짜 이전·이후(당일 포함)를 지원합니다. 임의 코드를 실행하지 않습니다.
- 필드: 지역, 사용승인일, 경과 연수, 지상 층수, 연면적, 주용도, 구조, 소유 구분, 내진설계, 기존 지원 여부.
- 지역·용도 등 문자열은 정확히 일치해야 합니다. 표기 차이는 담당자가 정규화해야 합니다. 숫자·불리언 누락은 추정하지 않습니다.
- `지원 대상`: 승인 조건을 모두 충족. `검토 필요`: 공고 미승인·근거 불일치·미해석 조건·정보 누락. `대상 아님`: 명시된 조건 미충족 또는 마감.
- LLM 추출은 자동 승인되지 않습니다. PDF·이미지 OCR 결과 자체도 담당자 검토가 필요합니다. 복합 OR, 예외, 신청자 자격 등의 조건은 미해석 항목으로 남겨 해결해야 합니다. 모델이 조건을 누락할 수 있으므로 인용 검증만으로 완전성을 보장하지 않습니다.
- 결과는 **지원 자격 대조를 돕는 검토 결과**입니다. 구조적 안전성 진단이나 기관의 최종 선정 결과가 아닙니다.
- 지역 공고 자동 수집, 세움터·정부24 대장 자동 조회, 소유자 전화번호 자동 조회는 구현되어 있지 않습니다. 현재는 사용자가 문서를 확보하여 등록합니다.

## 발송과 데이터 보호

- 실제 발송 API는 DB에 저장된 승인 공고와 건축물 정보를 다시 판정합니다. 연락 동의·수집 근거·유효한 동의일·전화번호가 필요하며 가상 예제는 발송할 수 없습니다.
- `(공고 ID, 건축물 ID)` 조합의 고유 키를 SQLite에 **제공자 요청 전에** 기록합니다. 동시에 요청해도 한 번만 접수합니다. 같은 공고에 대한 재안내는 현재 지원하지 않습니다.
- 타임아웃·네트워크 오류·불완전 응답은 `결과 확인 필요`로 기록하며 자동 재시도하지 않습니다. 제공자 콘솔에서 확인하세요. 중단 시 `접수 중` 기록도 재발송하지 않습니다.
- `접수 완료`는 Solapi 접수 상태이며 실제 배달 완료를 의미하지 않습니다. 배달 결과 웹훅은 현재 미구현입니다.
- SQLite는 `data/anjin.sqlite`에 저장됩니다. 연락처는 마스킹해서 표시하지만 DB 자체는 암호화하지 않습니다. 파일 접근 제어·디스크 암호화·보관 정책은 운영 환경에서 적용하세요.
- 인증 토큰은 탭의 `sessionStorage`에 보관합니다. 브라우저만 사용하는 정적 체험판은 `localStorage`에 데이터를 저장하며 여러 기기 간 동기화되지 않습니다. 서버 연결 시 데이터는 자동 병합되지 않습니다.
- 문서 분석 시 OpenAI로 문서가 전송됩니다. API의 `store:false`를 사용하나 제공자의 데이터 처리 정책을 별도로 확인하세요. 소유자 주민번호 등 불필요한 개인정보는 업로드 전 가리세요.

## Docker

```sh
docker build -t anjin .
docker run --rm -p 127.0.0.1:3000:3000 --env-file .env -v anjin-data:/app/data anjin
```

Docker의 기본 HOST는 `0.0.0.0`입니다. `.env`의 `HOST=127.0.0.1`은 제거하거나 `HOST=0.0.0.0`으로 바꾸고 `APP_ADMIN_TOKEN`을 설정하세요. Docker 예시는 작성되었으나 이 작업에서 컨테이너 빌드는 실행하지 않았습니다.

## API

| 메서드·경로 | 기능 |
| --- | --- |
| `GET /api/status` | 비밀값 없는 연결 상태 |
| `GET /api/state` | 공고·건축물·발송 내역 |
| `PUT /api/state` | 버전 비교 후 저장, 충돌 시 409 |
| `POST /api/analyze` | `{kind: "notice" 또는 "building", text}` 또는 `{kind, mime, data: "base64"}` |
| `POST /api/messages/send` | `{noticeId, buildingIds, message, confirmed:true}` |

`APP_ADMIN_TOKEN` 설정 시 `/api/status`를 제외한 API에 `Authorization: Bearer <token>`이 필요합니다. 쓰기 API는 같은 출처의 JSON 요청만 허용합니다.

## 검증

```sh
npm run check
npm test
```

기준일·마감 경계, 누락값, 인용 근거, 동의, CSV 인용·수식 방지, LLM·문자 응답 검증, 인증·수정 충돌·동시 발송과 영속 중복 방지 테스트를 포함합니다. 외부 분석·문자는 모의 응답으로 검증합니다. 실제 유료 API 호출 및 문자 발송은 실행하지 않았습니다. GitHub Actions가 동일 검사를 실행합니다.

## 구성

```text
public/              한국어 반응형 웹 UI (프레임워크·빌드 의존성 없음)
lib/rules.mjs        검증 및 결정적 자격 대조
lib/providers.mjs    OpenAI Responses / Solapi 어댑터
lib/csv.mjs          CSV 및 건축물 입력 정규화
lib/seed.mjs         가상 예제 데이터
server.mjs           HTTP 서버, 토큰 인증, SQLite, 발송 저널
samples/             CSV·공고문 입력 예제
tests/               단위·통합 테스트
```

정적 호스팅의 체험 화면은 동일한 UI와 판정 엔진을 사용하지만 서버 API·실제 분석·문자는 제공하지 않습니다. 위 Node.js 서버를 배포하면 전체 기능을 연결할 수 있습니다.
